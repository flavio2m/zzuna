# UI

## Antes de implementar

Sempre verificar componentes compartilhados em:

```text
lib/ui/shared/
```

Ordem de consulta:

```text
Buttons e ações clicáveis
→ lib/ui/shared/widgets/buttons/

Cards
→ lib/ui/shared/widgets/cards/

Campos de entrada
→ lib/ui/shared/widgets/forms/

Feedback visual (SnackBar, Dialog, etc.)
→ lib/ui/shared/feedback/
```

Reutilizar componentes existentes sempre que possível.

Não criar novos componentes quando já existir uma implementação equivalente em `ui/shared`.

### Campos de entrada

Utilizar componentes compartilhados da pasta:
```text
lib/ui/shared/widgets/forms/
```

Evitar uso direto de:
```dart
TextField
TextFormField
```
quando existir um componente compartilhado equivalente.

Não utilizar SizedBox ou Divider diretamente.
Utilizar:
- AppSpacing
- AppDivider
para manter os espaçamentos padronizados.

### Objetivo

Garantir:

* Consistência visual.
* Reutilização de código.
* Centralização de manutenção.
* Padronização da experiência do usuário.

## Quando criar Page

Criar Page quando a funcionalidade representar uma tela completa.

Exemplos:

```text
login_page.dart
home_page.dart
profile_page.dart
```

Estrutura:

```text
ui/[domain]/[feature]/
├── [feature]_page.dart
└── viewmodels/
    └── [feature]_viewmodel.dart
```

---

## Quando criar Widget

Criar Widget quando a funcionalidade for reutilizável.

Exemplos:

```text
logout_button.dart
user_avatar.dart
product_card.dart
```

Estrutura:

```text
ui/[domain]/[feature]/
├── viewmodels/
│   └── [feature]_viewmodel.dart
└── widgets/
    └── [widget].dart
```

## Regras

* Toda ação deve passar por ViewModel.
* Nunca acessar Repository diretamente da UI.
* Nunca acessar Service diretamente da UI.
* Utilizar Providers para obter ViewModels.
* Utilizar Commands para ações assíncronas.
* Utilizar AppSnackBar para feedback.
* Utilizar CommandStateExtension para tratar sucesso e erro.
* Utilizar DTOs para armazenar dados de formulários.
* Utilizar Validators para validar formulários.
* O botão da ação principal deve permanecer desabilitado enquanto o formulário for inválido.
* Campos com validação devem utilizar AppTextFormField dentro de AppForm.
* AppTextField deve ser utilizado apenas para entradas sem validação.

build():

```dart
final viewModel =
    ref.watch(exampleViewModelProvider);
```

initState():

```dart
final viewModel =
    ref.read(exampleViewModelProvider);
```

## Formulários

### DTO + Validator

```dart
final validator =
    RegisterUserDtoValidator();

final dto =
    RegisterUserDto(
      name: '',
      email: '',
      password: '',
    );
```

---

### Atualização dos campos

Os campos devem atualizar o DTO e reavaliar o formulário.

```dart
TextFormField(
  autovalidateMode:
      AutovalidateMode.onUserInteraction,
  onChanged: (value) {
    dto.setName(value);
    setState(() {});
  },
  validator:
      validator.byField(dto, 'name'),
)
```

---

### Controle de submissão

Criar um getter para verificar se o formulário é válido.

```dart
bool get _canSubmit {
  return validator
      .validate(dto)
      .isValid;
}
```

---

### Execução da ação

Sempre validar antes de executar o Command.

```dart
void _handleSubmit() {
  if (_canSubmit) {
    viewModel.command.execute(dto);
  }
}
```

---

### Botão principal

O botão principal deve permanecer desabilitado enquanto:

* O formulário for inválido.
* O Command estiver executando.

```dart
ListenableBuilder(
  listenable: viewModel.command,
  builder: (_, __) {
    return ButtonSave(
      onPressed:
          viewModel.command.value.isRunning ||
                  !_canSubmit
              ? null
              : _handleSubmit,
    );
  },
)
```

---

## Listener de Command

```dart
void _commandListener() {
  final commandValue =
      viewModel.command.value;

  commandValue.onSuccess((result) {
    AppSnackBar.showSuccess(
      context,
      'Operação realizada com sucesso',
    );
  });

  commandValue.onFailure((exception) {
    AppSnackBar.showError(
      context,
      exception?.toString() ?? 'Erro',
    );
  });
}
```

## Não fazer

* Regras de negócio.
* HTTP.
* Services.
* Repositories.
* StreamController.
* ScaffoldMessenger direto.
* Executar Commands sem validação prévia.
* Habilitar ações principais quando o formulário for inválido.

### Observação

A UI pode utilizar Validators para validar formulários.

As regras de validação devem permanecer centralizadas na camada:

```text
domain/validators/
```
